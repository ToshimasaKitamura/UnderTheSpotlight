# 修正PDCA（回し続ける仕組み）

バグ修正・改善を **Plan → Do → Check → Act** で回す。**Check が合格するまで繰り返す**のが要点。
各フェーズは既存の仕組み（原因特定の方針・チェッカー・開発ナレッジ）を使う。`/pdca` コマンドで開始できる。

```
 ┌──────────────────────────────────────────────┐
 │ Plan   症状を再現し、原因を"特定"する（推測しない）        │
 │        期待結果と「検証方法」を先に決める                  │
 ├──────────────────────────────────────────────┤
 │ Do     最小限の修正を1つ入れる（一度に複数いじらない）      │
 ├──────────────────────────────────────────────┤
 │ Check  bash Tools/check_all.sh を通す                    │
 │        ＋ 症状を再現→"解消"を確認 ＋ デグレ無しを確認       │
 │        ✗ なら試行ログに結果を書いて → Plan へ戻る          │
 ├──────────────────────────────────────────────┤
 │ Act    /log-fix で開発ナレッジに追記                      │
 │        一般則なら CLAUDE.md ルールへ昇格                  │
 │        再発を機械で防げるなら checker/テストを追加          │
 └──────────────────────────────────────────────┘
        Check ✗ → Plan に戻る（＝PDCAを繰り返す）
        Check ✓ かつ Act 完了 → その修正は「完了」
```

## 各フェーズの合格条件（ゲート）

- **Plan**: ①症状を再現できた ②原因を*特定*できた（「たぶん」で進めない＝CLAUDE.md）③期待結果と検証手順を書いた
- **Do**: 変更は原因に対する最小の1手。無関係な改変を混ぜない
- **Check**: `bash Tools/check_all.sh` が exit 0 ／ 症状が消えた ／ 既存機能が壊れていない（デグレ無し）
- **Act**: [開発ナレッジ.md](開発ナレッジ.md) に記録済み ／ 一般則は [../CLAUDE.md](../CLAUDE.md) へ昇格済み

## 繰り返しの原則

- **Check で不合格なら必ず Plan に戻る**。Do を勘で重ねない（CLAUDE.md「推測で修正を重ねない」）。
- 戻るときは**試行ログ**に「仮説・やったこと・結果（なぜ効かなかったか）」を残す。同じ手を二度試さないため。
- 3回以上ループしても Check が通らないときは、前提（再現条件・原因の特定）が誤っている。Plan からやり直す。

## 1修正あたりのテンプレート（作業中のメモ用）

作業中は下記を手元に置き、完了後は要点を [開発ナレッジ.md](開発ナレッジ.md) に転記する。

```
■ 課題:
□ Plan
  - 再現手順:
  - 特定した原因:
  - 期待結果 / 検証方法:
□ 試行ログ（Do→Check の繰り返し）
  - 試行1: 仮説= / 変更= / 結果=（✓/✗ 理由）
  - 試行2: ...
□ Check
  - check_all.sh: ✓/✗
  - 症状の再現→解消: ✓/✗
  - デグレ確認: ✓/✗
□ Act
  - 開発ナレッジ追記: ✓
  - CLAUDE.md 昇格: あり/なし（内容）
  - 再発防止(checker/テスト追加): あり/なし
```

## 関連

- Check の一括実行: `Tools/check_all.sh`（フォルダ構成＋仕様整合性＋コンパイルエラー痕跡）
- Act の記録: [開発ナレッジ.md](開発ナレッジ.md) ／ `/log-fix`
- 判断方針: [../CLAUDE.md](../CLAUDE.md)（原因特定・推測で重ねない・フォールバック禁止）
