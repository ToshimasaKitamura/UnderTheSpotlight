## 2026-10-12 4人未満でもカーソル4つ・アクションコマンドが4人入力待ちになる(tuning未割当で人数上書きがスキップ)
- **症状**: ワールドマップから1〜3人でプレイしても、カード選択のカーソルが4つ出る／アクションコマンドが4人分の入力待ちで進まない。実効人数が常に4のまま
- **原因**: 各フェーズの `ApplyTuning()` が冒頭 `if (tuning == null) return;` で早期リターンしていた。BattleScene では **全フェーズの `tuning` が未割り当て(fileID:0 = null)** のため、その直後に置いた `playerCount = BattleParty.Count(tuning)`(選択パーティから人数を決める処理)が**一度も実行されず**、`playerCount` は直列化既定の 4 のまま。cursor生成/ターンループ/アクションコマンドは `playerCount` 基準なので全て4人扱いになっていた
- **対処**: `playerCount = BattleParty.Count(tuning)` を **tuning null ガードの外(必ず実行される位置)** へ移動。対象: [CardSelectPhase](../Assets/Src/Card/CardSelectPhase.cs) / [ActionCommandPhase](../Assets/Src/MicroGame/ActionCommandPhase.cs) / [PartSelectPhase](../Assets/Src/UI/PartSelectPhase.cs) / [BombController](../Assets/Src/Utils/BombController.cs)。`BattleParty.Count` は tuning=null でも選択パーティ(`GameSceneManager.selectedParty`)から n を返し、選択情報が無い直接再生時のみ 4 にフォールバックする
- **再発防止**: 「シーンの Inspector 参照は未割り当て(null)のことがある」。null ガードの**後ろ**に必須処理を書くと、その参照が外れている環境で丸ごとスキップされる。必ず効かせたい処理はガードの**前**に置く。CLAUDE.md 昇格済み
- **関連**: [BattleParty.cs](../Assets/Src/Utils/BattleParty.cs), [CardSelectPhase.cs](../Assets/Src/Card/CardSelectPhase.cs), [ActionCommandPhase.cs](../Assets/Src/MicroGame/ActionCommandPhase.cs), [BombController.cs](../Assets/Src/Utils/BombController.cs)

## 2026-10-04 カードの一部テキストが「?」で表示される(美咲フォント描画の空化)
- **症状**: カードの文字の一部(特定の文字列)が「?」になる。全部ではなく「一部」だけ
- **原因**: [PixelFontRenderer](../Assets/Src/Utils/PixelFontRenderer.cs) の美咲フォント GL 描画で、`material.SetPass(0)`(アトラスのバインド)を **`RequestCharactersInTexture` より前**に呼んでいた。新規文字を含む文字列は Request でフォントアトラスが**再構築**されるため、先にバインドした**古いアトラス**のまま描画→その文字が空→`visible==0`→ビットマップ代替('?')に落ちる。既にアトラスにある文字だけの文字列は成功するので「一部」だけ「?」になる。さらに代替結果が textCache に固着して再発
- **対処**: 順序を **`RequestCharactersInTexture` → `SetPass(0)` → GL描画** に修正(再構築後のアトラスをバインド)。加えて、美咲描画が空で代替に落ちた結果は**キャッシュしない**(次回リトライ)＋警告ログに該当文字列を出す
- **再発防止**: 動的フォントを GL/低レベル描画するときは「**文字要求 → アトラス(マテリアル)バインド → 描画**」の順を厳守。順序違反は新規文字だけ化ける。CLAUDE.md 昇格済み
- **関連**: [PixelFontRenderer.cs](../Assets/Src/Utils/PixelFontRenderer.cs)

## 2026-10-03 弾幕HPバーが残量1で「1↔0」に点滅して見える
- **症状**: 弾幕中、HPが残り少ない(残量25%以下)とき、HPバーが 1 と 0 を往復するように点滅して見える
- **原因**: [SharedHpGaugeUI](../Assets/Src/UI/SharedHpGaugeUI.cs) の危険時演出が `if (!isDanger || blinkOn)` で**フィル(残量バー)の描画自体をON/OFF**していた。残量1のとき描画が点滅=バーが「1(表示)↔0(非表示)」に見える
- **対処**: フィルは常に描画し、危険時は `GUI.color` の**アルファを明滅**(1.0↔0.5)させる方式に変更。バーは消えず色だけ脈動して警告する
- **再発防止**: 「残量を表す要素」の点滅は**表示/非表示でなく色・輝度**で行う(消すと残量が増減したように誤認される)
- **関連**: [SharedHpGaugeUI.cs](../Assets/Src/UI/SharedHpGaugeUI.cs)

## 2026-10-03 弾幕移行時に上段キャラが下段の四隅窓へ写り込む / SpriteMask範囲でキャラが消える
- **症状**: AC→弾幕の移行でプレイヤーが下降する際、上段(P1)が下段(P3)の四隅窓に一瞬写り込む。さらに、対策で入れた SpriteMask のカスタム範囲設定により**四隅ポートレートが全く表示されなくなる**デグレを発生させた
- **原因**:
  1. 写り込み: `SpriteMask` は既定で**全スプライトに作用**する。四隅窓マスクが4つ常在し、キャラ画像が縦長なので、上段キャラが少し下がると下端が下段窓に重なり `VisibleInsideMask` でそこに描画される
  2. デグレ: 対策で各マスクに `isCustomRangeActive=true` + `front/backSortingOrder` を**同値(order)**で設定したが、front==back の範囲は実質空とみなされ、`VisibleInsideMask` のキャラがどのマスクにも拾われず**非表示**になった
- **対処**: SpriteMask のカスタム範囲方式は撤回。写り込みは**下降量を安全域に制限**して回避：静止時スプライト下端は下段窓上端の `innerH*0.15≈0.05vp` 上にある(`GetAllyPortraitPlacement` のクランプ)ので、退避の下降量を `exitDropViewport=0.035vp` 未満に抑え、下段窓へ到達させない。見た目は**縮小＋フェード**で「自分の枠内で消える」ように補う([DodgeVisuals](../Assets/Src/Dodge/DodgeVisuals.cs))
- **再発防止**: **SpriteMask の `frontSortingOrder==backSortingOrder` は使わない**(空範囲扱いで消える)。マスクのソート範囲での分離は実機確認必須。常在する複数マスク＋縦長スプライトの重なりは、マスク側でなく**動きの範囲**で制御するのが安全
- **関連**: [DodgeVisuals.cs](../Assets/Src/Dodge/DodgeVisuals.cs), [BattleFrameUI.cs](../Assets/Src/UI/BattleFrameUI.cs)

## 2026-10-03 ボスがすぐ倒れる／弾幕を1回終えると必ず勝敗画面に飛ぶ
- **症状**: ボスの体力が実質無く、少し攻撃する or 弾幕を1回凌ぐだけで勝利(or遷移)してしまい、ゲームとして成立しない
- **原因**: 本来の撃破判定は [BattleResultPhase](../Assets/Src/Battle/BattleResultPhase.cs) の `IsAllPartsDestroyed()`（全部位破壊）にあるのに、それを上書きする**仮ショートカットが2つ**残っていた。①[ActionCommandPhase](../Assets/Src/MicroGame/ActionCommandPhase.cs) が累計命中 `hitsToDefeatBoss=4` で BattleResult を飛ばして即勝利。②[DodgePhase](../Assets/Src/Dodge/DodgePhase.cs) が弾幕終了時に**無条件** `OnBossDefeated()` を呼び、1回凌ぐ＝撃破扱い
- **対処**: ①ACの閾値ショートカット(`hitsToDefeatBoss`/`cumulativeHits`)を撤去し常に BattleResult へ。②Dodge 終了後は `CardSelect` へ戻すだけにし、撃破判定/連戦進行は BattleResult に一本化。③ボスAの部位HPを合計8→16(頭6/腕6/足4)に引き上げ。これで「CardSelect→AC→Result(全部位破壊で撃破、未破壊ならDodge)→Dodge→CardSelect…」の正規ループが回る
- **再発防止**: **勝敗判定の正典は BattleResultPhase 1か所**に保つ。各フェーズに「仮の勝利/遷移」を散らさない。残す場合は `【仮】` を明記し、本実装前に撤去する。ボスHPのプレイ人数差(1フェーズ最大 playerCount 回×攻撃力)はプレイテストで調整(将来、人数スケーリング検討)
- **関連**: [ActionCommandPhase.cs](../Assets/Src/MicroGame/ActionCommandPhase.cs), [DodgePhase.cs](../Assets/Src/Dodge/DodgePhase.cs), [BattleResultPhase.cs](../Assets/Src/Battle/BattleResultPhase.cs), [BossA_Juggler.asset](../Assets/Data/Enemies/BossA_Juggler.asset)

## 2026-10-03 弾幕フェーズで四隅の味方枠が残りキャラと重なる
- **症状**: 弾幕(回避)フェーズ中、プレイヤーキャラは左右へ移動して浮遊するのに、カード選択時の**四隅の枠(窓)が表示されたまま**残り、空の枠とキャラ画像が重なって見える
- **原因**: 味方枠(`BattleFrameUI.allyFrames`)の表示制御を **CardSelectPhase だけが行っていた**（終了時に `ShowAllyFramesOnly()`）。`DodgePhase` は枠に一切触れず、カード選択で表示された枠が弾幕中もそのまま残っていた。キャラは `DodgeVisuals` が左右へ動かすため、空枠と位置がズレて重なる
- **対処**: `DodgePhase` に `BattleFrameUI` 参照を追加。`EnterSequence` 冒頭で `HideAllyFramesOnly()`（枠を隠し窓クリップも解除＝サイド浮遊中は全身表示）、`EndDodgeSequence` のプレイヤー復帰後に `ShowAllyFramesOnly()`（枠を復活＋四隅へ戻ったキャラを窓に収める）
- **再発防止**: **「フェーズをまたぐUI(味方枠)は、表示したフェーズだけでなく次フェーズの入口/出口でも状態を引き継ぐ」**。枠の表示責務が CardSelect に偏っていたのが根因。Dodge 突入/離脱で明示的に Hide/Show する

## 2026-08-10 オンライン対戦を「壊さずに」実装する（パッケージ未導入対策）
- **症状(未然防止)**: Netcode/UGS のような**未導入パッケージのAPI**を `using Unity.Netcode;` 等で参照すると、その型が見つからず**全スクリプトがコンパイル不能**になり、プロジェクト全体が最後の成功ビルド（＝古いコード）で固まる
- **原因**: 予定義アセンブリ(Assembly-CSharp)は導入済みパッケージしか参照できない。未導入のまま参照を書くと解決不能
- **対処**: 実装レイヤを **`#if UGS_NETCODE` で丸ごとガード**（[NetcodeRelayLobby.cs](../Assets/Src/Network/NetcodeRelayLobby.cs)）。抽象(`INetworkLobby`/provider)とUIは常時コンパイルし、未有効時は `UnavailableLobby` が**明確なエラー**を返す（フォールバックで握りつぶさない）。パッケージは manifest.json に追加するが、ガードOFF既定なので**バージョン相違でもゲームコードは壊れない**（Package Manager のみが1行を指摘）
- **再発防止**: 外部パッケージ依存コードは「常時コンパイルの抽象 ＋ `#if` ガードの実装 ＋ 未有効時の明示エラー」の3層で入れる。有効化手順は正典 [Networking_Design.md](Design/Networking_Design.md#3-実通信を有効化する手順一度きり) に集約
- **関連**: [Assets/Src/Network/](../Assets/Src/Network/), [Packages/manifest.json](../Packages/manifest.json), [Docs/Design/Networking_Design.md](Design/Networking_Design.md)

- **再発防止(別件)**: `Temp/`・`Library/`・`Logs/` は Unity 管理下。**Unity 起動中に消さない**（掃除は閉じてから）。CLAUDE.md 昇格済み

- **原因**: マップのデータ連鎖(ScriptableObject)が全て偽 `m_Script` guid で **Missing Script**。`WorldMap_1.asset`(script `d6e7f809…`≠実 WorldMapData `23c39833…`)と `Stage_1..5.asset`(script `c5d6e7f8…`≠実 StageData `75fcea5a…`)。中身(ステージ名・ノード座標・接続)は正しく揃っていたが、型として読めず `WorldMapSceneController.worldMap` が実質 null → `SpawnView` されず空表示
- **対処**: 6資産の `m_Script` guid を実型 guid に修正（アセット参照・Scene参照は元々正しいので guid 差し替えのみ）。5ノード(森の入口→森の奥→古い砦→嵐の丘→星見の塔)が表示・選択→キャラ選択へ遷移
- **再発防止**: Missing Script は**シーンだけでなく .asset(ScriptableObject)でも起きる**。「表示されない/データが空」時は `.asset` の `m_Script` guid が実スクリプトの `.cs.meta` guid と一致するか確認。CLAUDE.md「スクリプト参照」に該当
- **関連**: [Assets/Data/Stages/](../Assets/Data/Stages/), [Assets/Src/System/WorldMapSceneController.cs](../Assets/Src/System/WorldMapSceneController.cs)

## 2026-08-03 カードデータ(.asset)が3箇所に重複していた
- **症状**: `Assets/Data/Cards/`・`Assets/Resources/Data/`直下・`Assets/Resources/Data/Cards/` に同名カード資産が重複

- **対処**: 実使用の `Resources/Data/Cards/`（6枚）＋ `Resources/Data/StandardDeck.asset` に集約し、死んだ重複を削除。`Test.png` の Resources 重複も削除
- **再発防止**: **カードのマスターデータは `Assets/Resources/Data/`（Cards/ 配下＋StandardDeck）が正**。`Resources.Load` はパス依存なので Resources 内に置く必要がある。`Assets/Data/` 側に同じものを複製しない
- **補足**: `Player.png` は `Assets/Images/`（GUID参照13件）と `Assets/Resources/Images/`（`Resources.LoadAll("Images/Player")`）の両方が必要で、これは重複ではなく仕様
- **関連**: [Assets/Resources/Data/](../Assets/Resources/Data/), [Assets/Src/Battle/BattleStateMachine.cs](../Assets/Src/Battle/BattleStateMachine.cs)

## 2026-07-27 ゲームオーバーのボタンにシーン名（DontDestroyOnLoad / ResultScene）が表示される
- **症状**: ボタンのラベルが日本語ではなく「DontDestroyOnLoad」「ResultScene」等になる
- **原因**: `GUI.Button` のラベル描画中に毎フレーム例外。`GameFont.Body()` が返す `Font.CreateDynamicFontFromOSFont`（動的OSフォント）を、Unity 6 の IMGUI(TextCore) が `FontAsset.CreateFontAsset` で変換しようとして例外を投げ、ラベルが壊れていた（Editor.log のスタックで特定）
- **対処**: `GameFont.Body()` を、インポート済みフォント `Resources/Fonts/misaki_gothic` を最優先で返すよう変更。これで ResultScene のボタンとアクションコマンドUIの両方が解消
- **再発防止**: IMGUI の日本語は動的OSフォントを使わず、インポート済みフォントを使う（CLAUDE.md 昇格済み）
- **関連**: [Assets/Src/Utils/GameFont.cs](../Assets/Src/Utils/GameFont.cs)

## 2026-07-26 弾幕フェーズが正しく表示されない・調整値が反映されない

- **再発防止**: SerializeField の既定値は保存済みに反映されない点に注意（CLAUDE.md 昇格済み）
